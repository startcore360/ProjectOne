# EDU 360 V4.0 — Requirements-to-Code Gap Audit

**Repository:** `startcore360/ProjectOne`  
**Baseline inspected:** `master`, commit `8fd84a2` (1 Nov 2026)  
**Source baseline:** EDU 360 V4.0 deliverables 1–8, especially the Governance & Action Register (D2), Roles & Permission Specification (D3), API/OpenAPI contract (D5), Requirements Traceability & QA workbook (D6), and Security/Compliance report (D8).  
**Audit type:** source and CI inspection. No deployed environment, live API runtime, penetration test, or production database was available.

## 1. Executive finding

The repository is a functioning starter application, not a V4.0 implementation. It has a React/TypeScript frontend and Spring Boot API with authentication, courses, attendance, scores, and basic performance summaries. It does not yet implement the V4.0 tenant/institution architecture, full role/action authorization model, or the documented API surface.

Do not treat a documented operation mapping as proof that the operation exists in the repository. D6 explicitly says action tests are drafted and not run; the V4.0 Action Trace maps all 234 Phase 1 actions to contract operations, not to verified runtime handlers.

## 4. Security findings addressed in this branch

1. **Course membership enforcement:** Attendance and score bulk-write services previously checked that the teacher owned the course and that the submitted user existed, but did not verify that the student was enrolled in that course. A shared membership guard now rejects non-student and non-enrolled users before either write.
2. **Production cookie transport:** The production Spring profile now explicitly sets `app.auth.cookie-secure=true`. This does not change local development behaviour.

These changes close two narrow controls only. They do not provide tenant isolation, action-code authorization, OIDC/MFA, or a V4.0 security sign-off.

## 5. CI evidence and release blockers

The inspected master workflow run failed:
- Frontend lint passed, but Vitest found no test files and the frontend build did not run.
- Backend Maven verification passed.
- npm audit failed with 18 reported vulnerabilities (2 low, 3 moderate, 11 high, 2 critical); the Maven audit and Gitleaks stages did not run after the earlier failure.
- CodeQL Java autobuild failed, so analysis was skipped.
- PostgreSQL validation job was green only because it emitted a warning: `sql/run_all.sh` and SQL assets were missing from the repository. No migration tests ran.

The uploaded SQL package contains a runner and scripts designed to execute 97 acceptance tests on disposable PostgreSQL databases. It is not yet integrated into the branch in this change set; the database job must not be described as a successful validation until those assets are committed and CI actually executes them.
